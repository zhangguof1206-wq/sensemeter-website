# SenseMeter SEO 执行清单

## 执行原则

- 先验证索引与查询数据，再决定扩写范围。
- 所有参数、认证、交期、贸易条款和案例必须可核验。
- 每一批修改先在本地构建、抓取和表单回归，再部署。
- 邮件环境变量与现有 SMTP 配置不进入代码库，不在部署时覆盖。

## 第 0 阶段：建立基线（1 天）

| 任务 | 验收标准 | 负责人建议 |
|---|---|---|
| 导出 Yandex Webmaster 的 Searchable / Excluded / Crawl 数据 | 保存 URL、原因和日期 | 站点管理员 |
| 导出 GSC 页面与查询数据 | 最近 3 个月按页面、查询、国家拆分 | 站点管理员 |
| 记录询盘基线 | 有效询盘数、页面来源、产品型号 | 销售/运营 |
| 选定 10 个试点 URL | 5 产品 + 5 配件，优先有资料和商业价值的页面 | 销售 + 技术 |

## 第 1 阶段：技术加固（2–4 天）

### 1. Googlebot metadata 验证

1. 使用 GSC URL Inspection 查看 3 个代表页面的已抓取 HTML。
2. 确认 title、description、canonical 是否出现在渲染结果中。
3. 只有确认 description 未被识别时，才调整 Next.js metadata 输出策略。
4. 本地分别模拟 Googlebot、YandexBot、Bingbot 和 Chrome。

验收：四种 UA 均得到正确 title、description、canonical；构建通过；Lighthouse 不再报告 description 缺失。

### 2. 元数据批处理

- 修正 30 个长度异常标题。
- 补强 73 个过短描述，优先 62 个配件详情页。
- 不重复标题中的同义关键词，不使用城市或“俄罗斯”堆砌。

验收：所有可索引页保留唯一 title/description；标题清楚表达型号或类别，描述说明任务、适用场景和供应方式。

## 第 2 阶段：10 页内容试点（5–10 天）

### 产品页模板

1. 一句话选型结论。
2. 适用介质与应用场景。
3. 经验证的关键参数表。
4. 样气、压力、流量、过滤与安装条件。
5. 输出、供电、通信和系统集成。
6. 型号差异与选型步骤。
7. 可选附件和相关配件。
8. PDF、证书、校准和质量文件。
9. 从中国发往俄罗斯的可选交付方式与报价所需信息。
10. 3–5 个真实常见问题。

### 配件页模板

1. 配件用途和解决的问题。
2. 与哪些仪表、接口和介质兼容。
3. 材料、尺寸、孔隙、压力或流量等已确认参数。
4. 安装与维护注意事项。
5. 定制边界与询价所需数据。
6. 相关产品、类别和应用链接。

验收：每个页面都能让采购或工程师判断“是否适用、还需提供什么信息、下一步如何询价”；所有数字有来源。

## 第 3 阶段：实体与内部链接（3–5 天）

- 为试点产品添加经过验证的 `Product` JSON-LD，不虚构 `Offer`。
- 从对应应用页添加自然语言产品链接。
- 从产品页链接到兼容配件和相关应用。
- 从配件详情返回类别页、相关配件和适用产品。
- Organization 仅添加真实企业资料页到 `sameAs`。

验收：结构化数据无错误；每个试点页至少有 2 个有上下文的入口和 2 个有业务意义的出口链接。

## 第 4 阶段：效果复盘（上线后 4–8 周）

对比试点页和未修改同类页：

- 索引状态与抓取频率。
- 非品牌展示量和点击量。
- 平均排名和查询覆盖。
- 联系页到达、表单提交和有效询盘。
- 搜索词是否与页面真实业务匹配。

只有试点证明有效后，才将模板扩展到其余产品和配件页。

## 暂不建议

- 不建议一次性生成大量地区页或关键词变体页。
- 不建议购买批量垃圾外链。
- 不建议在无价格、库存或固定交易条件时伪造 Product Offer。
- 不建议为了字数复制制造商全文或重复模板段落。
- 不建议在没有真实数据前重构 URL 或大规模改版。
