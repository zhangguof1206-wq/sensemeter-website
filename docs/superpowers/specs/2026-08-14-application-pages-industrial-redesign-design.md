# SenseMeter 应用页工业化视觉改版设计

## 1. 目标

将 SenseMeter 的应用详情页从重复卡片式页面改为更成熟的工业网站布局：增加真实工业场景图片、建立深浅区块节奏、强化工程选型信息，并让推荐产品更易比较和进入询价流程。

本次只改应用详情页的展示架构，不改品牌定位、产品参数、应用网址、推荐产品关系或询价业务逻辑。

## 2. 已确认范围

- 覆盖 5 个俄文应用页及其 5 个英文对应页。
- 保留当前 `PageShell` 页面顶部，包括 Logo、品牌说明、导航、目录下拉、搜索框和 RU/EN 切换。
- 保留当前页脚、Telegram 浮动入口、Cookie 提示和全站询价入口。
- 保留所有应用页现有 URL，不增加重定向，不改变 canonical、hreflang 或 sitemap 路径。
- 使用项目内已有真实工业场景图和真实产品图，不用生成图冒充业务现场。
- 不新增未经确认的技术参数、认证、案例、库存、授权代理或服务能力声明。

## 3. 页面结构

### 3.1 工业场景首屏

- 页面顶部继续使用现有全站导航，其下为应用页首屏。
- 首屏使用对应应用场景图全宽铺设，深蓝遮罩保证俄文和英文标题清晰。
- 首屏包含面包屑、应用类别、唯一 H1、简介、询价按钮和推荐产品锚点。
- 桌面端标题位于左侧，右下保留两项简短的使用方式摘要；移动端摘要移入正文流，避免遮挡图片和按钮。

### 3.2 应用价值说明

- 使用参考图中的左右分栏结构：左侧短标题、中间细线识别符、右侧说明正文。
- 不使用悬浮卡片，不重复首屏文案。
- 该区块回答应用问题与测量价值，为搜索引擎和生成式搜索提供清晰、可引用的背景说明。

### 3.3 测量位置与使用场景

- 使用一张高图加四张横向图片的非对称工业图片网格。
- 每项包含场景名称、简短说明和必要的产品锚点。
- 内容由现有应用概述、亮点和使用方式重新组织，不增加未经确认的客户案例。
- 同一应用缺少五张独立图片时，可复用该应用的 hero、inline 和 CTA 图片，并通过不同裁切位置维持视觉变化；不得借用会造成错误业务含义的图片。

### 3.4 深色工程选型区

- 使用深蓝全宽背景和对应工业图片构成页面中的主要视觉转折。
- 展示四组现有选型步骤：介质或测量目标、量程或压力、安装与采样、输出与控制。
- 将现有 RFQ 清单合并到选型信息中显示，确保气体、压力、量程、安装、信号、显示、数量和文档要求等有效信息不丢失。
- 选型内容仅指导客户准备参数，不自动推断型号或技术结论。

### 3.5 推荐产品区

- 保留每个应用页当前 `recommendedSlugs` 的产品集合和顺序。
- 第一款产品使用大图与深色规格面板突出展示，其余产品采用两张横向重点卡和三张简洁产品项。
- 规格文本继续读取产品目录中的真实参数，不在应用页单独复制或编造参数。
- 每个产品项链接到现有产品详情页，主要按钮继续使用“Подробнее / Learn more”语义，不替代询价流程。

### 3.6 FAQ 与最终询价

- FAQ 使用无外框的分隔线列表，页面中保留可见问题和答案。
- FAQ 旁显示应用相关图片与参数询价入口。
- 页面末尾增加一条深色工业图片 CTA，复用现有联系页参数预填链接。
- 保留 `FAQPage` JSON-LD，并新增与可见面包屑一致的 `BreadcrumbList` JSON-LD。

## 4. 双语数据与组件架构

- 建立一个应用页展示组件，由俄文和英文路由共同使用。
- 将当前 5 个俄文页面中的页面内容迁移到结构化数据，不改写其事实含义。
- 每个应用主题在一个独立数据文件中同时保存 RU/EN 内容、图片和推荐产品关系，便于校对语言一致性。
- 俄文 5 个静态路由文件继续保留，但只负责 metadata、内容读取和渲染；英文动态路由继续保留。
- 页面区块拆分为首屏、场景网格、选型区、产品区和 FAQ/CTA 组件，避免形成新的超大组件。
- 全局 CSS 只保存通用应用页样式钩子和响应式规则，具体布局优先使用现有 Tailwind 体系。

## 5. SEO 与 GEO 约束

- 每页保持一个 H1，H2 按应用价值、测量位置、选型、推荐产品和 FAQ 顺序组织。
- 保留每页现有 title、description、canonical、hreflang、Open Graph 图片和 sitemap 收录。
- 图片 alt 使用场景或产品的准确描述，不堆砌关键词。
- 保留完整可见 FAQ，结构化数据中的问题与答案必须和页面一致。
- 内链继续连接应用页、推荐产品详情页和带 `application` 参数的联系页。
- 不隐藏正文给搜索引擎，不使用只在客户端加载的关键内容。

## 6. 响应式与可访问性

- 桌面端以 1440px 为主要验收宽度，兼容 1280px。
- 移动端以 390px 为主要验收宽度；所有多栏区块改为单列，标题、按钮和俄文长词不得产生横向溢出。
- 顶部导航沿用现有响应式逻辑，不在应用页另建导航。
- 图片容器使用固定宽高比或明确高度，避免加载时布局跳动。
- 按钮和链接保留可见键盘焦点，装饰元素使用 `aria-hidden`。
- 尊重 `prefers-reduced-motion`；不增加持续运动、视差滚动或自动轮播。

## 7. 性能边界

- 优先复用 `public/assets` 中现有应用图和产品图。
- 首屏只加载一张主要背景图；首屏以下图片使用延迟加载。
- 不引入新的 UI、动画或轮播依赖。
- 不把完整产品参数复制进应用数据，避免内容重复和维护漂移。

## 8. 验收标准

- 10 个应用页使用同一视觉系统，俄英内容和图片对应正确。
- 页面顶部与当前网站保持一致，没有更换或重做导航。
- 页面结构与已确认视觉图一致：工业首屏、分栏介绍、非对称场景图、深色选型区、重点产品组合、FAQ 和图片 CTA。
- 所有现有 URL、语言切换、推荐产品链接、询价链接和 FAQ JSON-LD 正常。
- 1440px 与 390px 下无横向滚动、文字遮挡、图片空白或按钮溢出。
- `check:applications`、`check:application-links`、`check:seo`、`check:yandex-urls`、`check:ui`、`check:i18n`、`check:catalog`、`check:accessories`、`typecheck` 和生产构建全部通过。
- 修改完成后先提交本地代码并提供本地截图；用户确认后才进入 Ubuntu VPS / PM2 手动发布步骤。

## 9. 非本次范围

- 不改首页、目录页、产品详情页、配件页或询价表单字段。
- 不修改 SenseMeter Logo、品牌色和顶部导航结构。
- 不新增应用主题、产品型号、技术参数或外部图片来源。
- 不在未确认前部署服务器或提交 Yandex 重新抓取。
