# SenseMeter 全站内容完善与 Yandex 索引改造设计

## 1. 背景与证据

本设计基于本地最终版网站、Yandex Webmaster 两份导出数据、现有制造商 PDF、选型表及已确认的首页和配件目录设计。

Yandex 最新变更日志包含 108 次事件、42 个已知 URL。按每个 URL 的最后一次事件还原，当前为 4 个 `SEARCHABLE`、38 个 `LOW_DEMAND`。可搜索页面是俄语首页、俄语关于、俄语目录和英文 SF82 产品页。20 个俄语产品页曾被加入搜索，随后在 2026 年 7 月 5 日至 7 日集中移除。全部事件的 HTTP 状态均为 200，因此主要问题不是抓取被阻止，而是页面价值、搜索需求和内容相似度。

本地最终版当前 sitemap 有 154 个 URL：

- 8 个俄英核心页面；
- 6 个俄英法律页面；
- 10 个俄英应用页面；
- 44 个俄英仪器详情页；
- 2 个俄英配件总览页；
- 12 个俄英配件分类页；
- 72 个俄英配件详情页。

本地逐页渲染统计显示，10 个应用页面约 438 至 520 词；44 个仪器详情页约 90 至 154 词；72 个配件详情页约 136 至 182 词。现有仪器和配件详情页结构正确，但独特内容不足。

## 2. 目标

1. 在不改变已确认视觉方向的前提下，完善俄语和英文内容。
2. 让全部商业页面具备明确搜索意图、独特正文、可靠技术参数和采购价值。
3. 修正 sitemap、canonical、hreflang、法律页索引和 Yandex 提交流程。
4. 全部内容、功能、排版和图片通过本地生产环境检查后，再由用户确认是否部署。
5. 部署后由用户按明确步骤完成服务器操作和 Yandex Webmaster 提交。

## 3. 不在范围内

- 不宣称 SenseMeter 是 Michell、Rotronic、Vaisala 或 AII 的官方授权代理。
- 不虚构俄罗斯本地公司、仓库、库存、交期、固定质保或本地售后网络。
- 不增加未经资料验证的测量性能、认证、兼容性或固定配件规格。
- 不在用户确认前部署服务器或向 Yandex 提交页面。
- 不重新设计已确认的首页、目录和配件视觉风格，仅为承载新增内容做必要布局扩展。

## 4. 已确认的业务口径

- 公司定位：独立供应商和技术选型服务商。
- 履约方式：境外供货，无俄罗斯本地公司、仓库或常备库存；交期和运输按正式报价确认。
- 支持范围：提供选型、资料和安装前技术沟通；质保、维修和返厂安排按品牌、型号及正式报价确认。
- 语言目标：俄语和英文页面均争取进入 Yandex 搜索。
- 上线策略：先完成全部 22 个仪器、36 个配件及相关页面的俄英内容，再统一上线。
- 配件性质：图片、`SM-*` 内部目录型号和参数用于展示代表性结构与定制能力；最终尺寸、材质、接口和性能以正式报价为准。

## 5. 索引范围

最终 sitemap 只包含 148 个商业页面：

- 8 个核心页面；
- 10 个应用页面；
- 44 个仪器详情页；
- 2 个配件总览页；
- 12 个配件分类页；
- 72 个配件详情页。

6 个隐私、Cookie 和个人数据同意页面保持可访问，使用自引用 canonical 和唯一的 `noindex, follow`，不进入 sitemap。现有 thank-you 页面继续 noindex 且不进入 sitemap。

## 6. 内容数据架构

### 6.1 仪器数据

避免继续扩大现有 `catalog.ts`。将产品类型和通用工具与品牌内容拆分：

- `src/data/products/types.ts`：产品、SEO、FAQ、参数来源等类型；
- `src/data/products/michell.ts`；
- `src/data/products/rotronic.ts`；
- `src/data/products/vaisala.ts`；
- `src/data/products/aii.ts`；
- `src/data/products/index.ts`：聚合导出与查找函数。

每个产品数据至少包含：

- `targetQuery`、`secondaryQueries`、`searchIntent`；
- `seoReady`、`lastReviewed`；
- `sources`：内部可追溯的 PDF 或选型表文件名；
- 俄英概述、参数、特点和应用；
- 俄英选型条件、安装说明、限制条件、型号区别、FAQ 和询价资料清单；
- 相关应用、产品和配件 slug。

### 6.2 配件数据

保留当前按类别拆分的数据文件，在现有结构上增加：

- 搜索意图和关键词；
- 功能与适用系统；
- 可定制范围；
- 兼容设备和安装方式；
- 维护、清洁、更换建议；
- 使用限制；
- 定制流程；
- 产品专属 FAQ；
- 询价所需图纸和参数；
- 相关配件与分类。

共享免责声明由组件统一输出，产品独特正文必须存放在数据文件中，不能由模板自动拼接成近似页面。

### 6.3 页面组件边界

仪器与配件详情页面拆成职责清晰的小组件，例如：

- 页面标题与采购摘要；
- 参数表；
- 选型指南；
- 安装与限制；
- 应用说明；
- FAQ；
- 询价资料清单；
- 相关页面链接；
- 技术资料与参数确认说明。

组件只负责展示，具体产品内容全部来自结构化数据。不得把 22 个产品或 36 个配件的文案硬编码进大型页面组件。

## 7. 页面内容规范

### 7.1 仪器详情页

每个页面目标为约 350 至 600 个有价值的俄语词和英文词，不以灌水达到字数。内容包括：

1. 产品用途和采购场景；
2. 已验证的测量范围、精度、压力、输出、接口和认证；
3. 介质、量程、安装环境、防爆要求和输出信号等选型条件；
4. 安装和使用注意事项；
5. 同系列型号区别和适用边界；
6. 典型应用及推荐理由；
7. 4 至 6 个型号专属 FAQ；
8. 询价前需要提供的信息；
9. 相关应用、替代型号和配件；
10. 资料来源和最终规格确认说明。

技术参数优先使用现有制造商 PDF 和选型表。无法确认的参数不写成保证值。

### 7.2 配件详情页

每个页面目标为约 250 至 450 个有价值的俄语词和英文词。内容包括：

1. 代表性图片和内部目录型号说明；
2. 功能、适用系统和工作介质；
3. 材质、孔径、尺寸、接口、温度和压力等可定制范围；
4. 兼容设备和安装方式；
5. 维护、更换和清洁建议；
6. 不适用条件和使用限制；
7. 定制流程及客户需要提供的图纸或参数；
8. 4 至 6 个产品专属 FAQ；
9. 相关配件和分类链接；
10. 最终参数以正式报价确认为准的说明。

不显示固定库存、固定交期或未经确认的性能保证。

### 7.3 应用页面

现有应用页保留较完整的正文深度，并补充：

- 工艺问题和测量目的；
- 关键选型参数和测量位置；
- 推荐产品及理由；
- 安装建议、常见错误和维护；
- 型号选择对照表；
- FAQ 和询价资料清单；
- 指向相关产品的明确内部链接。

现有 `/applications/glove-box-oxygen-analysis` 搜索范围过窄。将俄英页面统一迁移到 `/applications/industrial-oxygen-analysis`（英文为 `/en/applications/industrial-oxygen-analysis`），覆盖工业气体、惰性环境、实验室和手套箱。两个旧地址分别单跳永久重定向到对应语言的新地址，应用页总数不增加。

### 7.4 核心页面

首页、目录、关于和联系页面统一采用真实经营口径，清楚说明独立供应商身份、境外供货、技术支持范围及质保按报价确认。不得制造俄罗斯本地库存或官方授权印象。

## 8. 关键词与重复控制

每个可索引页面必须有一个主要查询意图。主要关键词不能在同语言的多个页面之间重复占用。应用页承接行业和问题型查询，产品页承接型号与采购型查询，分类页承接品类和选型型查询。

自动检查需去除导航、页脚、询价说明等共享文本后再计算相似度：

- 相似度达到 0.72 时警告；
- 相似度达到 0.80 时失败；
- FAQ、选型条件和限制说明必须包含产品特有信息，不能只替换型号。

俄语和英文分别检查语言纯度、关键词映射和自然表达。

## 9. Yandex 技术设计

### 9.1 Sitemap 与 hreflang

- sitemap 只输出 148 个返回 200、允许索引、自引用 canonical 的商业页面；
- sitemap 保留真实内容更新时间，不使用构建时间；
- 删除 sitemap 中的语言版本扩展；
- 在每个 HTML 页面的 `<head>` 中输出完整、双向的 `ru`、`en` 和 `x-default` hreflang；
- 俄英页面分别自引用 canonical，禁止跨语言 canonical。

Yandex 已不再支持使用 sitemap 传递语言版本，语言关联以 HTML `<head>` 标记为准。

### 9.2 Robots、canonical 与重定向

- 保留 `Allow: /` 和 Yandex `Clean-param`；
- robots.txt 引用唯一 sitemap；
- 不使用 robots.txt 阻止法律页面，使机器人能读取 `noindex`；
- 每个页面只输出一个绝对 canonical；
- HTTP、www、旧氧气应用地址和其他重复地址使用单跳永久重定向；
- 不允许 canonical 链、重定向链或 canonical 指向重定向页面。

### 9.3 初始 HTML 与结构化数据

- 关键标题、正文、链接和图片说明必须在服务器返回的 HTML 中；
- Organization 和 WebSite 结构化数据保留；
- 产品和配件详情页使用 BreadcrumbList；
- 目录和分类页使用 ItemList；
- 页面存在可见 FAQ 时才输出 FAQPage；
- 因为没有公开固定价格和 Offer，不伪造 Product Offer、库存或评价数据。

### 9.4 IndexNow 与 Yandex Webmaster

- 增加 IndexNow 密钥文件和只提交真实变化 URL 的脚本；
- 本次部署中 148 个商业页面均属于新建或实质更新，可在部署验证后提交一次；
- sitemap 在 Yandex Webmaster 的 Sitemap 工具中提交，不放入页面重新索引工具；
- 页面重新索引优先提交首页、目录、应用页和高需求产品页，按当天配额执行；
- IndexNow、sitemap 和重新索引只促进发现和抓取，不承诺收录。

## 10. 自动检查与生产验证

### 10.1 全量自动检查

154 个当前页面 URL 均需在本地生产模式逐页请求和渲染，另外检查 thank-you 页面及重定向地址。检查项目包括：

- HTTP 状态和重定向链；
- title、description、H1、canonical、robots、hreflang；
- sitemap 包含关系；
- 正文深度、语言纯度和相似度；
- 内部链接、PDF、图片和询价入口；
- 图片自然尺寸、alt、加载状态和缓存安全文件名；
- 横向溢出、文字重叠、空白区域和缺失内容；
- 结构化数据可解析且与可见内容一致。

### 10.2 内容准确性检查

- 22 个仪器页面逐项核对制造商 PDF 和选型表；
- 36 个配件页面逐项核对结构化字段、代表性图片说明和定制范围；
- 无法确认的技术声明删除、降级为可选项或标记为报价确认；
- 不复制制造商长段营销文案，不出现来源网站品牌和联系方式。

### 10.3 视觉检查

- 使用本地生产构建，不以开发模式作为最终证据；
- 桌面和手机尺寸为全部页面生成截图与缩略总览，并逐页检查；
- 对长标题、长参数、无 PDF、相关产品较多等边界页面做全尺寸检查；
- 使用 Chrome 和 Edge 检查主要页面模板；
- 重点检查配件图片背景、contain 显示、裁切、清晰度和跨浏览器一致性；
- 检查键盘导航、目录下拉、移动菜单、语言切换和 RFQ 路径。

### 10.4 必须通过的命令

在现有检查基础上增加内容质量和渲染检查，并至少通过：

- catalog、accessories、applications、application links；
- SEO、i18n、UI、Yandex URL list；
- 内容深度、重复度、索引范围和来源完整性；
- TypeScript 类型检查；
- Next.js 生产构建；
- 本地生产环境全量 URL 抓取与截图检查。

## 11. 失败处理

- 技术资料不明确：停止该页面内容定稿，使用现有文件继续核对；仍无法确认时向用户索取资料。
- 页面内容过于相似：补充真实差异或调整关键词归属，不用同义词替换绕过检查。
- 图片异常：从原始文件重新处理并使用新文件名，禁止依赖混合模式掩盖背景问题。
- 页面构建或渲染失败：修复后重新运行相关专项检查和完整生产构建。
- Yandex 提交失败：保留已验证网站，不重复无变化提交；根据 Webmaster 错误信息处理。
- 任何检查未通过：不进入用户验收和部署步骤。

## 12. 用户验收与部署门槛

1. Codex 完成内容、代码、自动检查和视觉检查。
2. Codex 启动本地生产预览并提供检查清单、主要页面入口和已知限制。
3. 用户再次检查页面内容、排版和图片。
4. 只有用户明确回复“确认上线”，才进入服务器部署。
5. 需要用户手动操作时，Codex 暂停实施并逐步指导；每一步确认后再继续。
6. 部署后重新验证线上 200 状态、robots、sitemap、canonical、hreflang、表单和图片。
7. 线上验证通过后才执行 Yandex sitemap、页面重新索引和 IndexNow 提交。

## 13. 工程与提交要求

- 避免继续扩大 `catalog.ts` 和 `site.tsx`，新增内容按品牌、类别和组件职责拆分；
- 数据、展示和 SEO 规则分别维护，避免页面组件硬编码业务内容；
- 自动检查覆盖新增字段和索引规则，防止后续回退；
- 每次提交保持功能完整并使用中文 Commit Message；
- 保留用户已有设计和无关改动，不执行破坏性 Git 操作。
