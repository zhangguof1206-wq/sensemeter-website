# 询盘场景带入与俄语露点增补设计

用户已确认两项都做，先修复询盘场景，再增补俄语内容。范围沿用此前已展示的方案。

## 第一项：询盘场景

中英文联系入口读取既有 `application` 查询参数，仅匹配现有五个应用 slug。服务器按语言取得应用标题，再传给联系页和表单的用途输入框；不把完整应用数据带进客户端。未知、空值和重复参数不预填。用途使用默认值而不是只读值，客户仍可修改；保留原有 `model` 产品预选、邮件字段、隐私同意、发送状态和成功事件，不改密钥或邮件服务。

验收涵盖五种应用与两种语言、无参数/未知/重复参数、型号预选、用途可编辑及提交后的字段。GitHub 浏览器测试只操作隔离的构建服务器，拦截表单 POST，不发送真实询盘；桌面/移动截图和结果保存在检查附件。正式站点发布与真实邮件送达需另行验收。

## 第二项：俄语露点

仅修改 `src/data/applications/compressed-air-dew-point.ts` 的俄语选型文字、询盘参数和 FAQ。解释压力露点与常压露点不能直接对比，以及取样条件、读数稳定和记录要求。不统一指定流量、等待时间、压力或精度，不承诺标准合规、排名或 FAQ 富媒体展示。内容依据已核验的 Vaisala 安装/取样资料。

保留 URL、标题、英文内容、产品推荐、canonical/hreflang、图片及既有页面组件。已有内链不重复添加。验收检查内容断言、英文本保持一致、现有应用/国际化/SEO 检查、正式构建及 GitHub 浏览器回归。

## 结果验证

两项分别中文提交。提交、检查通过与实际发布明确区分；继续保留已有产品页观察窗口。上线后比较同口径 GSC 曝光与点击，并人工记录有效询盘，不把预填修复或检查分数当作已获得增长。
